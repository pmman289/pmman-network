# 管理后台开发规范

管理后台采用 Vue 3、TypeScript strict、Element Plus、Vue Router、Pinia、Axios 和 Vite。
使用中文语言包，遵循常见中台的侧栏导航、顶部面包屑、内容卡片、查询列表、编辑弹窗和详情抽屉模式。
这是本项目后续后台开发的统一约定，相关指引已写入根目录 `AGENTS.md`。

## 工程边界

`admin/` 是独立 Web 应用，不引用 Windows 客户端的 Tauri API，拥有独立依赖与锁文件。
`src/views/` 放业务页面，`layouts/` 放控制台布局，`components/` 放跨页面组件，
`api/` 放请求封装和接口适配，`types/` 放服务端契约，`stores/` 放共享状态，
`composables/` 放分页、操作反馈和确认逻辑，`styles/` 放统一主题与响应式规则。

页面不得直接使用 fetch、拼接 HTML、访问 DOM 生成业务列表，或复制请求拦截逻辑。
优先使用 Element Plus 的表格、表单、弹窗、确认框、抽屉、消息、空状态和加载组件。
业务代码使用明确类型，避免 `any`；遵循 Vue、TypeScript 的 ESLint 推荐规则和 Prettier 格式。

## 页面与交互

| 页面 | 管理内容 | 主要交互 |
| --- | --- | --- |
| 运行概览 | 用户、节点、连接、地址资源 | 实际数据统计、节点摘要、最近设备 |
| 用户管理 | 用户角色、状态、能力、密码、账号删除 | 搜索筛选、分页、新建、授权、密码及删除确认弹窗 |
| 节点管理 | 待接入/在线状态、WireGuard/UDP 探测地址、返回路由表、资源版本、可选开关 | 创建接入凭据、下载一键部署脚本、取消待接入、搜索分页、配置弹窗、一键更新 |
| 设备与租约 | 用户、节点、双栈地址、流量模式、连接 | 搜索筛选、分页、详情抽屉、撤销确认 |
| 地址池 | 命名地址池、多段 CIDR、保留地址、双栈主池、各族容量与占用 | 批量粘贴、独立主池、冲突及删除阻塞提示 |
| 网络配置 | 自动地址池路由、附加内网 CIDR | 自动项只读，附加项独立保存，不覆盖地址池 |
| 客户端日志 | 用户上报的诊断报告、所属用户、上报时间和文件大小 | 按用户或报告编号搜索、分页、下载 |

客户端日志位于“运维管理 → 客户端日志”。列表 `GET /v1/admin/diagnostics`，下载
`GET /v1/admin/diagnostics/{user_id}/{report_id}`；两者均要求管理员会话。
报告文件沿用 `PMMAN_DIAGNOSTIC_DIR` 挂载目录及每账户最近 5 份的保留策略，
旧报告无需重新上报即可下载；被清理的报告返回 404。下载通过认证请求获取文件，
不将 Bearer Token 放在 URL 中。搜索与分页和现有后台一致在前端执行。

列表使用稳定 row-key、明确列宽、超长内容提示、右侧固定操作列以及统一分页。
用户地址分配遵循 [多地址池规范](ADDRESS-POOLS.md)：IPv4/IPv6 独立草稿，池内固定必须选定具体地址，不提供随机固定。候选地址由服务端游标分页和精确 IP 查询，不枚举 IPv6 子网；保存时使用配置版本并再次检查占用。

旧列表 API 返回全量列表，因此当前搜索和分页在前端执行；数据量扩大后应迁移到服务端查询和分页，
不能将前端分页描述为服务端分页。查询条件变化后回到第一页。

表单必须有字段标签、必填及格式校验，服务端仍负责最终校验。编辑时使用独立草稿，
刷新列表不能覆盖打开的编辑弹窗；地址池未保存内容也不得被刷新覆盖。
提交期间显示 loading、防止重复请求，成功后刷新真实数据，失败后显示可理解的错误并允许重试。
禁用用户、停用节点、迁移路由表、移除能力、撤销连接和修改地址池都需要说明影响并确认。
不使用浏览器原生 prompt/confirm 作为业务交互。

使用统一主题变量、间距和字体；避免业务页面任意添加全局样式。
窄屏下侧栏改为抽屉，筛选栏换行，弹窗不超出视口，宽表格仅在表格区域横向滚动。
图标按钮必须有可读标签，状态同时显示文字，不只依靠颜色。
概览不展示无来源的模拟 CPU、流量或延迟指标。

“最后活动”来自设备的历史 `last_seen_at`。主控重启撤销旧连接时必须保留该字段，
不能用清零时间代替离线状态；历史零值、缺失或无效日期统一显示“未记录”，
不伪造当前时间。`pnpm --dir admin test` 覆盖日期格式化回归。

## 权限与请求状态

邀请授权、邀请码及注册记录见 `docs/INVITATIONS.md`。这两个新列表使用服务端分页/筛选，
不沿用现有全量列表的前端分页。邀请权限编辑使用共享 `InvitationGrantForm`，只编辑独立受邀授权。
公开注册页是独立构建入口 `/register`，请求由 `api/registration.ts` 处理，不能引用后台认证拦截器。
长授权表单限定弹窗高度，表单区域滚动，保留可见的标题及保存/取消操作。

后台路由需要管理员登录；普通用户不能进入。未知路由提供 404 页面。
Bearer 会话仅存 sessionStorage，密码不持久化。登出或 401 时清理会话和页面数据并返回登录页；
403 显示权限不足，不冒充成功。请求超时为 15 秒，统一处理参数错误、记录不存在和数据冲突。
不输出凭据、请求认证头或完整 Axios 错误对象。

数据读取采用完整快照，失败时保留上一份数据并显示过期提示；界面明确显示更新时间并提供刷新。
并发读取采用请求版本号，旧请求不能覆盖新请求；旧会话的响应不能写回新会话状态。
保存后读取可以取代正在进行的旧读取，确保更新结果不会被刷新竞态覆盖。
前端权限只是交互控制，实际权限始终由主控管理 API 校验。

### 删除账号

用户列表通过 typed API 调用 `DELETE /v1/admin/users/{username}`，成功返回 204。
仅管理员可操作，禁止删除当前账号及最后一个可用管理员；前端禁用不能代替服务端校验。
删除弹窗须明确目标和影响，要求输入区分大小写的完整用户名；提交期间禁止重复操作和关闭。
失败保留确认弹窗及真实服务端错误，成功后重新读取列表，不只删除本地行。

主控在同一 PostgreSQL 事务中删除账号与授权、撤销设备、将转发置为待释放、撤销仍可使用的邀请码，
并记录审计；提交成功后才发布内存状态并使会话失效。节点沿用心跳同步移除 peer、回程路由和转发规则，
确认前不重新分配其公网端口。历史设备、转发事件和邀请注册记录保留，不提供恢复账号操作。

## 构建、部署与验证

在本地 WSL 执行：

```sh
cd /mnt/d/workspace/pmman-network-client/admin
pnpm install --frozen-lockfile
pnpm build
```

`build` 依次执行 Prettier 检查、ESLint（不允许警告）、Vue 类型检查和生产打包。
开发时使用 `pnpm dev`，默认 API 代理为 `http://127.0.0.1:8787`；可设置
`PMMAN_ADMIN_API=https://network.pmman.tech` 使用公网 API，不将密码写入环境文件或源码。

输出写入忽略目录 `server/admin-dist/`，Rust 使用 include_dir 将资源嵌入主控二进制。
先构建后台再运行 Cargo；`server/build.rs` 跟踪资源变化，确保仅修改前端也会重新嵌入。
入口 `/admin` 和 `/admin/` 返回 HTML，Hash 路由避免额外的 SPA 回退规则；
入口不缓存，带内容哈希的静态资源使用长期 immutable 缓存，缺失资源返回 404。
资源随二进制发布，不依赖公网 CDN 或远端 Node.js。

Windows 执行 `scripts/deploy-txgz.ps1 -Version <version>` 完成本地前端构建、Linux 测试、静态 musl 编译与公网部署；后续推荐将 `build-server-release.ps1` 与 `publish-server-release-txgz.ps1` 分开执行。
远端仍只运行已有项目服务。后台重写不改变 Windows 客户端的连接协议。

验收应覆盖管理员/普通用户登录、路由及会话恢复、搜索与空状态、表单校验、
成功/失败反馈、危险操作确认、节点路由表配置、设备详情，以及桌面/窄屏布局。
使用真实公网 API 和 Playwright，截图放入 `output/playwright/`，结果写入 `docs/PROGRESS.md`。
不因纯展示改动重复整套 WireGuard 验收；如更改连接 API 或数据生命周期，再运行相应真实网络验收。

节点接入、保存及地址池保留规则见 `docs/NODE-ONBOARDING.md`。所有地址池网段自动合并至客户端内网路由，与独立保存的附加内网 CIDR 去重后下发至 WireGuard `AllowedIPs`。自动项不得回写附加配置，删除池不得误删手工路由。连接时节点 DNS 排在本地 DNS 之前，本地 DNS 作为备用。
节点凭据仅在创建响应及当前弹窗持有；关闭弹窗即清空，不放入共享状态或浏览器存储。
