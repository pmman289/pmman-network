# Pmman Network 硬编码与配置持久化审计

审计日期：2026-10-06`r`n范围：主控、节点、Windows 客户端、管理后台、安装/更新包与生产发布脚本。

## 结论

本轮已修复会影响生产连接闭环的配置耦合：客户端不再猜测节点网关，节点接入配置会保存 DNS/双栈分流路由，主控正式运行强制使用持久化路径，客户端/节点缺少主控地址时会明确报错，用户和节点配置写盘失败时不会提交内存变更。进一步审计补齐了会话撤销、禁用节点边界、客户端发布回滚和验收凭据检查。

## 已修复项

### 节点网络配置闭环

- `NodeNetworkConfig` 传输节点实际 IPv4/IPv6 网关、DNS 和双栈分流路由。
- 节点注册上报接口配置；主控将生效配置放入客户端 `DeviceConfig`。
- Windows service 只对主控返回的可选网关地址发起探测，没有网关地址时不会使用默认地址冒充成功。
- 接入向导不预填实际网关地址，接入记录、环境文件和一键部署脚本包含 DNS/分流配置。
- 管理员可在节点编辑页修改网关、DNS 和分流路由；配置以主控持久化的管理员覆盖为准，并提示同步节点本机配置。

### 运行时与持久化

- 客户端找不到 `pmman-client.json` 时明确提示缺少主控配置，不再静默访问 localhost。
- 节点 `PMMAN_MASTER_URL` 为必填环境变量。
- 节点探测监听、节点名称、WireGuard 接口名和项目专属 systemd 服务名为必填环境变量；缺失时节点拒绝启动，不再落到通用 demo 值。
- 正式主控启动前强制检查 `PMMAN_DATABASE_URL` 和资源目录；缺少 PostgreSQL 时拒绝启动，不回退到默认数据。
- 地址池、用户、节点、设备和网络设置写入 PostgreSQL；大文件仍采用临时文件、同步和原子替换。
- 用户、节点和客户端发布文件的临时文件名包含随机 UUID，避免并发请求复用固定 `.tmp` 文件；客户端新发布包使用摘要绑定文件名，旧包不会在新 pointer 成功前删除。
- 过期会话在认证时清理；账户停用/重置密码和 `/v1/auth/logout` 会立即撤销 Bearer 会话。管理后台退出时会调用撤销接口，而不是只清除浏览器状态。管理员未完成首次改密时，服务端拒绝管理 API，但允许密码接口完成改密。
- 用户修改密码采用“先生成替代快照、持久化成功后再提交内存”的事务顺序；磁盘写入失败不会造成运行中密码与重启后密码不一致。
- 节点代理创建失败会撤销本次已分配设备，自动恢复登录的迟到响应不会覆盖退出或新登录；客户端构建脚本统一 Tauri 与 service 的更新版本，未发布显示标签与内部 SemVer 分离。
- 禁用节点仍可使用已有节点凭据心跳以接收 peer 清理，但不能重新注册或下载节点资源；节点仍不会提供 HTTP 管理面。
- 公网验收脚本不再回退到 `admin123`、`pmman123` 等默认凭据，必须通过环境变量提供真实验收账户。
- 一键节点部署使用节点 ID 派生的项目专属 systemd 服务名，并写入 DNS 与双栈分流表文件。

## 仍需明确的产品边界

- 活动设备租约和会话仍是运行时状态；主控重启后要求客户端重新建立连接。地址池与用户/节点配置不会因此丢失。若要实现主控重启后无感续租，需要另设 lease store，不应复用配置文件。
- 管理员修改节点网络字段只改变主控的生效配置；目标 Linux 节点的 WireGuard 接口、DNS 和分流文件必须同步修改或重新执行部署脚本。页面已给出提示，避免把“配置已保存”误认为“节点内核已变更”。
- `scripts/txgz`、`scripts/wireguard-demo.ps1`、`scripts/verify-*` 中的固定地址仅属于公网验收/开发脚本，不进入发布程序；后续可继续将 txgz 域名、IP 和目录改为外部部署参数。

## 发布包检查

- 当前发布源码不导入浏览器 fixture，不包含测试账号、测试节点或默认密码。
- 客户端发布包不包含 `localhost:1420`；主控和节点资源由发布清单及 SHA-256 校验保护。
- `admin` 使用 Vue 3、TypeScript 和 Element Plus；构建前应继续执行格式、Lint、类型检查和生产构建。
