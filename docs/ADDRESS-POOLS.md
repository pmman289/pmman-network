# 多地址池与双栈独立分配

## 管理方式

后台“资源管理 → 地址池”维护命名地址池、地址段和保留地址。一个池可同时包含 IPv4、IPv6，也可仅包含一种地址族。每行填写一条 CIDR，支持大量 `/32` 和 `/128`；不同池的同族地址段不能重叠。

分别选择 IPv4、IPv6 主地址池。用户默认两族自动分配并跟随主池；在“用户 → 地址租约”中分别设置：

- 自动分配：复用符合当前策略的地址，否则从对应池查找空闲地址。
- 池内固定：选择地址池，再选择一个具体地址。不会随机固定，也不会推导另一地址族。
- 手动指定：填写不带前缀的单个地址，允许池外地址；不能占用其他用户或节点网关的地址。

连接仍需取得一对双栈地址。任一族耗尽或配置无效时，整个分配失败，不会悄悄换池或降级单栈。用户在满池中已持有的地址仍可转为池内固定。

## 可用地址与路由

IPv4 `/0`—`/30` 排除原始段的网络、广播地址；`/31` 和 `/32` 的主机均可用。IPv6 普通段排除子网地址，`/128` 可用，不存在广播地址。先计算每个原始段的主机集合，再合并，不能将相邻 `/32` 聚合后重新扣除网络和广播地址。

不可分配单播地址、显式保留地址和已知节点网关会被排除。新地址段不固定扣除第二个地址；旧池迁移时仍保留其原网关保留项。单播检查另外排除 IPv4 零网段、回环、链路本地、组播/保留范围，以及 IPv6 未指定、回环、IPv4 映射、链路本地和组播范围。

所有地址池的 IPv4/IPv6 网段自动加入客户端内网路由，包括离散 `/32`、`/128`；不只包含主池或当前用户的来源池。下发时与管理员配置的附加内网 CIDR 合并去重，适用于内网、分流和全局模式。地址池创建、修改或删除后，新连接和配置查询自动使用当前集合，无需手工维护对应路由；已有客户端需重新连接以安装新路由。

自动路由从已提交的地址池配置派生，不写回手工 CIDR 列表。删除或缩小地址池只移除其自动来源，不删除管理员单独配置的同名路由；保留地址仍属于网段路由，不因禁止分配而变得不可访问。后台网络配置分别展示自动地址池路由和附加内网 CIDR。节点仍按实际租约管理 `/32`、`/128` 返回路由；公网宣告和 BIRD/OSPF 仍由管理员维护，不随主控自动改写。

## 生效与清理

策略、主池和自动分配范围的变更不打断当前连接。下次连接时，只重新分配不再符合策略的地址族。

地址变化前，主控必须确认旧节点已清除旧 peer 和返回路由。指向变更地址的旧端口转发进入 releasing，等待入口节点确认；未变更地址族的有效映射可按现有重连流程恢复。历史 released/expired 映射也必须由所属入口节点明确确认规则已删除，租约超时不代替 nftables 清理确认。未确认时连接返回 409，旧设备及地址保持隔离，稍后可重试。节点离线不能作为“清理完成”的依据。

池内固定地址不能通过收缩地址段或修改保留列表被移除。跟随主池的池内固定地址不属于新主池时，需先调整用户策略，再切换主池。删除池必须解除主池、用户策略和未释放租约引用。

收缩地址段后，原池的未释放地址仍计入占用和待释放统计，即使已在新范围之外；剩余容量仅扣除当前可用范围内的占用，因此迁出期间两者之和不一定等于新容量。

## 数据与接口

PostgreSQL schema 5 增加 `address_pools`、`address_pool_segments`、`address_pool_exclusions`、`address_pool_defaults`、`user_address_policies`、`address_leases`、`address_forward_cleanup`。地址使用 `inet/cidr`，未释放地址由部分唯一索引保证全局互斥。转发清理确认按设备、转发 ID 和所属节点持久化，主控重启不丢失待确认状态。

连接分配和用户策略保存，在同一事务更新租约及兼容的 users/devices 文档，成功后才发布内存状态。继续使用既有 devices → users 锁顺序，再获取地址池锁。数据库版本检查和事务锁拒绝过期快照；不支持多主控主动/主动缓存同步。

管理员 API：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET/POST | `/v1/admin/address-pools` | 查询、创建池 |
| POST/DELETE | `/v1/admin/address-pools/{id}` | 编辑、删除池 |
| GET | `/v1/admin/address-pools/{id}/addresses` | 查询具体地址 |
| GET/POST | `/v1/admin/address-pool-defaults` | 查询、修改双栈主池 |
| GET/POST | `/v1/admin/users/{username}/address-policy` | 双栈分配策略 |
| POST | `/v1/admin/settings/internal-routes` | 单独保存内网 CIDR |

所有地址配置写入要求当前 `revision`；删除使用查询参数 `revision`。过期版本返回 409。用户策略分别包含 `ipv4`、`ipv6`，每项为 `{mode, pool_id, address}`；模式为 automatic、pool_fixed 或 manual，空 pool_id 表示跟随主池。manual 不携带 pool_id；automatic 不携带固定 address。

地址查询参数：family=4/6、segment、status=available/occupied/all、address（精确 IP）、cursor（上一页最后地址）、limit（默认 20、最多 100）、user_id（允许列出该用户已持有的候选地址）。查询不锁定地址，保存时重新检查。容量通过十进制字符串返回；IPv6 不做全网段枚举。

旧地址池读取接口保留主池兼容摘要，容量最多截断到 u64；新后台按各池双栈字符串统计，不使用该摘要做地址选择。旧单池和旧成对静态写入接口返回 409，避免旧管理工具覆盖新配置或绕过选址要求。普通客户端、节点的连接协议不变。

## 迁移与回滚

首次启动读取当前 PostgreSQL 网络、用户、设备配置，在同一事务创建主池及现有租约。保持原地址和固定策略；池外固定地址迁移为手动地址。后续启动只读关系表，不用旧 JSON、环境默认值或旧网络文档重新生成池。已有关系记录损坏时拒绝启动。

上线前按现有发布流程备份 PostgreSQL、镜像与配置。旧主控不理解新池和独立策略，因此回滚必须恢复发布前数据库备份，不能只切回旧镜像；上线后新增的业务数据应先另行备份，不能静默丢弃。无需升级节点或客户端，不修改 BIRD、OSPF、DNS 和节点宿主机路由。

标准发布脚本先暂停旧主控写入，再备份数据库及原 public 表清单。失败自动回滚时清除升级新增的表并恢复旧 dump，避免残留新地址池配置；仅 `pg_dump --clean` 不能移除旧 dump 中不存在的新表。回滚脚本的独立 WSL Docker 验证可执行 `PMMAN_RELEASE_DOCKER_TEST=1 python3 -m unittest discover -s scripts/txgz -p test_server_release.py -v`，只使用临时专属 PostgreSQL 容器，不连接生产。

## 验证

常规检查：Admin 格式、lint、类型、构建与测试；WSL musl 主控、节点和协议测试。地址池专项位于 `server/src/address_pool_tests.rs`。

PostgreSQL 专项仅使用专属测试数据库，设置 `PMMAN_ADDRESS_POOL_TEST_DATABASE_URL`，数据库名称必须包含 `pmman_address_pool_test`，再运行：

```sh
cargo test --locked --manifest-path server/Cargo.toml --target x86_64-unknown-linux-musl address_pools::tests::postgres_ -- --ignored --test-threads=1
```

浏览器使用独立数据库的真实 API，不把本地控制面和模拟节点确认当作真实 WireGuard、P2P 或公网端口转发验收。每次发布的实际测试结果与剩余项记录在 `docs/PROGRESS.md`。
