# 按需客户端互联

## 产品约定

P2P 默认开启，可在线关闭/开启并持久化。访问另一在线客户端的 IPv4/IPv6 时按需创建会话；无业务流量不建立全网直连，双向业务活动维持会话，空闲 30 秒后释放直连。首包立即经节点发送，同时进行双向 UDP 探测；验证候选地址后优先直连。直连数据未及时确认则用同一 WireGuard 密文经节点补发，不更换虚拟 IP、不重建隧道、不要求应用重连。关闭 P2P 时仍可通过节点互联。

Windows 客户端启动 P2P UDP socket 后会异步尝试 UPnP IGD：只为这个随机 UDP socket 申请短期 UDP 映射，并把网关返回的公网地址加入候选集合；每两分钟续租，关闭 P2P、断开或服务退出时尽力删除映射。UPnP 不映射 WireGuard 隧道端口，不开放 HTTP 控制面，也不携带用户凭据。没有 IGD、路由器拒绝映射、SOAP 超时或映射失效都不会阻断连接，仍使用节点反射地址、双栈候选和认证 relay。映射租约为 5 分钟，异常进程退出时由网关自动过期。

首包送往中转后，若直连已认证成功但该包仍未确认，立即在新直连路径补发同一密文/序号，接收端去重。这样中转暂时不可用时也不会为已经可用的直连等待 WireGuard 握手重试；节点中转始终是可用性回退而非首次直连的成功前置条件。

## 实现边界

复用现有开源 WireGuard 的加密、握手、反重放和 Windows 驱动；RustCrypto HMAC/SHA-256 保护传输层身份和探测。当前不是完整 ICE/TURN 实现：不支持穿透的 NAT 或 UDP 策略通过经过身份认证的节点 UDP relay 承载。主控 HTTPS 是唯一客户端信息交换渠道；节点没有 HTTP 服务，也不接收用户 bearer token。

系统 WireGuard 的授权 peer 仅包含对方 /32、/128 和本地 UDP 传输端点，没有预先保活。内核首次发送目标流量时产生密文/握手，应用传输层因此启动该 pair，避免通过周期读取计数猜测流量和切换 AllowedIPs。公网数据始终为 WireGuard 密文，节点中转也不能解密客户端间的数据。UDP 探测回复只代表候选端点可达，不代表直连已建立；只有同一端点完成真实 WireGuard 密文 DATA/ACK 交换后，状态才提升为 `direct`。探测候选在提升前显示为 `probing`，连续三次真实直连数据由 relay 修复后进入 5 秒冷却，避免状态在 `direct`/`relay` 间快速振荡。

Windows 同步创建仅属于 PMMan 隧道接口的 ActiveStore 主机路由，peer 撤销时删除；不能假设运行 `wg set` 会创建系统路由。传输 socket 固定在物理下层接口，每 10 秒重新发现/绑定接口，注册刷新当前 NAT 反射地址。断路补发等待根据直连 RTT 调整（120–1000 ms），避免高延迟路径误回退。反重放使用固定 4096 位窗口，避免每包扫描集合。`direct` 表示同一候选端点已完成真实传输层 DATA/ACK 确认，仍不能单独证明对端应用业务可用；验收必须同时检查 WG 公钥、握手及 TCP/UDP 真实负载。

UDP 传输版本为 `PMMP2P02`，节点与客户端需一起升级。中转外层复用内层已签名 source/destination，只保留 magic、kind、timestamp 和 HMAC，不重复两次 UUID。1280 字节内层 IP 包、WireGuard 开销、两层认证头和 IPv6 UDP/IP 总计 1490 字节，避免在普通 1500 字节链路上因中转封装触发分片；嵌套 relay、身份不匹配和签名错误均拒绝。

P2P 探测接口是增强能力，不是建隧道前置条件：没有可用公网候选地址、接口尚未完成初始化或绑定候选失败时，传输层仍启动并使用认证节点 relay；后台每 10 秒重新发现接口。这样无公网 IPv4、Wi-Fi 切换和启动竞态不会阻断普通客户端连接。

节点选择同样不把探测丢包误判为节点离线：只要主控最近 heartbeat 标记节点健康，且所有 UDP/ICMP 探测均被当前网络策略过滤，客户端仍会尝试该节点的 WireGuard endpoint；此时不填写虚假的 RTT，最终状态仍必须由本次 WireGuard 握手和业务流量确认。有任一探测成功时，自动选择只在成功样本中按 RTT 选择最低延迟节点。

主控根据在线设备、公钥、账户启用状态提供带短期节点授权的目录。每次连接轮换设备传输 token；pair token 从双方随机 token 派生。节点轮询主控同步授权；离线/撤销/账户禁用立即撤销下一次授权同步，授权同步失败 15 秒后 fail closed。目录仅是配置预取，不代表已建立会话。

这里的 15 秒是 relay 授权有效期。WireGuard 网关另有 30 秒主控授权租约，由独立 watchdog 检查：主控 HTTP 阻塞不会阻止过期处理；过期先停用该节点专用接口，再清理 peer 和返回路由，失败项保留重试。新认证快照先清理旧状态，成功后才恢复接口。整批同步共享剩余租约截止时间，单个内核命令最多等待 3 秒，批次结束和接口恢复后再次检查租约，不能用慢操作延长授权。

Windows 同名隧道的创建、移除、远程撤销和目录更新共用会话互斥锁。旧会话的 HTTP 响应返回后，在锁内重新确认该会话仍有效，避免断开重连后迟到的撤销或目录响应破坏新隧道。

节点模式下客户端每 10 秒续租主控授权；60 秒无有效心跳即撤销旧公钥，节点的下一次同步移除它的网关 peer 和返回路由。迟到的心跳不能重新激活旧会话，必须重新连接；原设备地址租约仍保留并供重连复用。此租约与互联目录 30 秒在线窗口、节点主控租约分别检查，避免客户端崩溃后遗留永久在线网关 peer。

## 验收要求

- A/B/C 多账户 IPv4/IPv6 按需互联，未访问的 pair 保持 idle。
- 首包中转、快速直连；持续 TCP/UDP、切换期间不要求重连；阻断直连后节点补发与恢复。
- 双方开关、重启保存、空闲释放、活跃会话保持、掉线/撤销/密钥轮换。
- 精确 peer WireGuard 握手、实际业务校验与 direct/relay 字节计数；禁止用 UI 假状态代替。
- 本地 MSVC 和 WSL musl 构建，txgz 公网节点，多客户端通过 Hyper-V SYSTEM broker 提交规范产物，使用明确网络 profile，不在物理主机运行待测程序。

功能准出还需上述实测证据；单元测试、构建或同一 NAT 内直连不能单独证明所有 NAT 穿透或公网验收。

`scripts/run-p2p-hyperv.ps1` 默认提交三成员 PrivateNat request group。guest 检查每个目标 IPv4/IPv6 的 TCP/UDP 数据、双方在线开关、直连故障中转与恢复、30 秒 idle 和再次按需激活、断开重连的公钥轮换及地址复用。状态中的公开 `publicKey` 用来核对准确握手，不用非零握手行数替代身份验证。guest 的 `progress.json` 可经 broker live evidence 按需采集。

runner 在物理宿主只执行构建/可信管理 API/只读 SSH，不运行 PMMan 客户端。公网证据保存于忽略目录 `artifacts/p2p-<group>-public-evidence.json`；只采集项目节点的公开握手与路由，不调用可能暴露私钥的 `wg dump`。结束后只断言该组公钥和分配地址的 peer/路由消失，不要求其他用户的连接为空。

`scripts/p2p/guest-offline-install.ps1` 可用同一 acceptance launcher 经 broker 的 `NetworkProfile=None` 单独执行离线安装、真实 WebView 加载、客户端窗口、后台 IPC、默认 P2P 和唯一产品入口检查。结果记录安装前是否已有 WebView/WireGuard；已有运行时的 guest 不能证明缺失依赖的安装路径。
