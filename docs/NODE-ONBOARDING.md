# 节点接入与地址分配

## 管理员接入流程

打开 `https://network.pmman.tech/admin#/nodes`，点击「接入节点」。
每个节点使用唯一 ID、由节点自动生成和管理的 WireGuard 接口及公钥、WireGuard UDP 地址及 UDP 延迟探测地址。
客户端仅向主控获取信息；节点无 HTTP 监听，不接收用户凭据，主动向主控同步 peer 任务与安装结果。
主控预建接入记录，生成绑定节点 ID 的专属凭据；未预建节点、错误凭据及跨 ID 使用凭据均被拒绝。
`PMMAN_NODE_TOKENS` 旧的未绑定白名单不再生效。

1. 在主控中创建待接入节点，填写节点 ID、名称、区域、WireGuard 接口名、返回路由表和公网地址；此时节点尚未安装，不能也不需要填写 WireGuard 公钥。
2. 开放 WireGuard 与独立探测 UDP 端口，节点不需要 HTTPS 域名、证书或反向代理。
   两种 UDP endpoint 可使用域名或 IP，IPv6 endpoint 使用 `[地址]:端口`，探测与 WireGuard 不能占用同一端口。
3. 创建后下载「一键部署脚本」。凭据只在创建响应和本次弹窗出现，不会通过列表返回或写入浏览器存储。
   脚本在目标 Linux 主机上从主控 HTTPS 下载版本化 `pmman-node` 资源，校验主控返回的 SHA-256，写入 `node.env` 和 systemd 服务并启动；节点进程随后生成并保护私钥、创建 WireGuard 接口、配置地址和监听端口。
   未保存凭据时，取消「待接入」记录并重建即可；取消立即作废原凭据。
   未填写可选 IPv4/IPv6 分流路由时，脚本不会创建空分流文件或设置对应环境变量；节点启动不会因未启用分流而失败。
4. 节点首次启动时使用本机私钥计算 WireGuard 公钥，通过节点专属凭据向主控注册。主控收到后才显示公钥并允许客户端使用该节点；管理员页面中的公钥是只读状态，不接受手工修改。
5. 节点首次注册时会上报实际 WireGuard 接口名，主控在节点配置的“路由广播”标签生成对应的 BIRD 模板。模板只供管理员复制或下载，主控不会自动修改节点上的 BIRD、OSPF 或策略路由。
   主控资源目录由 `PMMAN_NODE_RESOURCE_DIR` 指定，包含 `manifest.json` 和 `pmman-node-<sha256>`。
   发布脚本会把本地 WSL 构建的静态 musl 节点二进制及清单上传到该目录；主控只允许绑定该节点 token 下载资源。
6. 节点注册成功后每秒向主控拉取任务并回报 peer 安装结果；首次真实心跳后显示在线，15 秒无心跳则离线。
   节点心跳收到管理员下发的新资源版本后，会通过同一 HTTPS 主控下载、校验、原子替换二进制并重启自身 systemd 服务。
   客户端并发发送带随机标识的 UDP 包，每节点三次采样、每次 400ms 超时，取成功样本的中位 RTT。
   默认自动选择最低 RTT，也可手动指定可达节点。探测无回包不会降级为 HTTP 或假定成功。

```ini
[Unit]
Description=PMMan node
After=network-online.target
Wants=network-online.target
[Service]
EnvironmentFile=/opt/pmman/node.env
ExecStart=/opt/pmman/pmman-node
Restart=on-failure
RestartSec=3
[Install]
WantedBy=multi-user.target
```

节点进程需要配置 WireGuard 和路由的系统权限；当前 demo 使用 root。
启动前确认独立接口已存在，主控 HTTPS 可访问，WireGuard/探测 UDP 入站防火墙开放。
节点程序负责注册、任务拉取、安装确认和 peer/主机路由管理，接口、NAT 和上游路由由部署层准备。
主控确认本次设备 ID、公钥、配置版本和返回表安装成功后才返回客户端配置，最长等待 8 秒；超时或安装失败自动撤销。
只完成注册不能证明隧道可用，必须继续验收真实握手和双栈流量。

## 版本更新与参数编辑

管理员在节点列表的「配置」中修改返回路由表、启用开关和每客户端限速；保存后由下一次心跳生效。
「一键更新」会把当前主控资源清单的版本写入节点期望状态，节点主动下载并重启，不需要主控反向 SSH，也不向节点暴露 HTTP 服务。
更新期间该节点的 WireGuard 接口会短暂重启；节点服务失败会由 systemd 按原策略拉起，主控列表会显示节点实际版本与待更新版本。
资源发布必须先更新 `node-resources/manifest.json`，清单中的文件名只能是 `pmman-node-*`，文件大小和 SHA-256 必须匹配。

## 双栈网络准备

第一主机地址预留为网关，默认 `10.88.0.1` / `fd88:1000::1`，不得分给客户端。
节点需要能访问内部网络；内部网关和上游路由必须能返回客户端地址池。
「返回路由表」是节点在该表中安装客户端 IPv4 `/32` 和 IPv6 `/128` 路由的配置。
节点同时为每个在线客户端安装按目的地址匹配的 `ip rule`，将回包导向该返回路由表，
避免回包误走 `main` 表的默认出口；断开、租约过期和返回表变更时会一起清理路由与规则。
节点仍不负责自动创建 BIRD/OSPF 宣告或上游路由，管理员需要按拓扑配置外部路由。
全局模式还需要上游转发/NAT。新客户端的境外分流由客户端版本内置的 cnipgen 双栈规则生成，节点不再需要配置 `PMMAN_IPV4_SPLIT_ROUTES_FILE` 或
`PMMAN_IPV6_SPLIT_ROUTES_FILE`；这两个变量仅为旧客户端兼容保留。`PMMAN_DNS_IPV4`、`PMMAN_DNS_IPV6`、`PMMAN_DNS_UPSTREAMS` 仍由节点负责 DNS 服务，下载的基础配置不包含拓扑特定项。
`pmmandns` 由节点进程管理，在节点 WireGuard 网关地址监听 UDP/TCP 53，并按主控配置向上游 DNS 转发；没有显式 DNS 监听地址时使用 WireGuard 网关地址。生产环境使用主控管理的 V2Fly/Xray `geosite.dat`，默认分类为 `cn` 和 `geolocation-!cn`；节点通过节点凭据下载、校验并缓存后本地加载。旧的 `domestic_rules`、`foreign_rules` 和默认分组仍兼容，用于旧配置和显式覆盖。节点注册时将配置同步到主控，由管理员覆盖配置后通过心跳下发到节点。客户端只查询节点 pmmandns，节点无结果时再交给本地 DNS。详细资源格式见 `docs/PMMANDNS-GEOSITE.md`。
修改返回表或停用节点时，后台会确认影响，再通过心跳同步。已注册节点用「停用」撤销连接，
「取消接入」仅适用于从未注册的记录，避免删除节点记录后丢失 peer 清理依据。

## 主控保存与初始化

`PMMAN_NODE_STORE=/opt/pmman-network-dev/node-registry.json` 保存接入凭据、注册信息、启用开关和路由表。
主控在提交配置前写入临时文件、同步并原子替换；Linux 文件权限为 `600`。
存储失败不会显示保存成功。目录需预先存在并允许主控写入，配置文件不得公开下载。
主控重启恢复接入记录，但不信任旧心跳时间，等待节点新心跳；节点注册/心跳请求超时为 10 秒，心跳失败会尝试重新注册。

生产部署不设置 `PMMAN_NODE_BOOTSTRAP_FILE`，不会自动创建、更新或覆盖任何节点。
管理员必须在主控「节点管理」中显式创建节点，下载一次性部署脚本后在目标 Linux 主机执行。
节点资源包可以随主控发布，但只有管理员创建的节点接入记录才能下载和注册。
节点记录、账户记录、地址池和内网 CIDR 配置均持久化；会话和设备租约仍是运行时状态，重启主控后活动会话与租约需要重新建立。

已创建节点的「配置」按「基础信息」「网络与 DNS」「路由与限速」分组，支持修改名称、区域、WireGuard 公网接入地址、UDP 探测地址、服务端公钥、返回路由表、pmmandns 监听地址、国内/国外上游 DNS、域名规则、默认分组、启停和限速。修改 pmmandns 配置后由节点下一次心跳动态生效，不需要暴露节点 HTTP 服务。
公网地址是客户端使用的 advertised endpoint；修改不会替代节点主机上的 WireGuard 监听配置，节点主机端口和防火墙仍需同步调整。

## 地址池约束

IPv4 池只接受 `/0` 至 `/30`。排除网络地址、广播地址和首个主机地址（网关），客户端容量为总地址数减 3。
例如 `/24` 容量 253，默认分配从 `.10` 开始，耗尽后补 `.2` 至 `.9`；`/30` 仅分配偏移 2。
`/31` 和 `/32` 作为客户端池被拒绝，本模型不使用点对点 `/31` 的 RFC 3021 例外。
IPv6 没有广播地址；双栈地址使用相同主机偏移，保留偏移 0 和 1。
IPv6 池必须足够容纳所有对应 IPv4 偏移，统计按双栈客户端租约计算。

分配、租约复用、池变更校验和容量统计使用同一可分配判定。
保留地址上的已撤销旧租约重新分配；活动异常租约先撤销，再重连。
池变更不能让已有租约变成网络/广播/网关地址，也不能破坏双栈偏移对应。
已撤销租约仍预留给原用户，因此「已分配」包括撤销租约；「可用」与分配器剩余数量一致。

## 验收与故障排查

### 节点 DNS

将节点网关填入 DNS 地址时，需要完整的 pmmandns 上游配置。三个上游字段全部为空时，主控会生成默认国内上游 `223.5.5.5`、`114.114.114.114` 和国外上游 `8.8.8.8`、`1.1.1.1`，管理员可修改；默认分组为空时设为国外。主控启动会对符合条件的旧记录做同样补全并保存，节点接入和保存配置也使用相同规则。已有自定义上游、规则、geosite 开关和默认分组不被覆盖；部分填写但缺少另一组时仍报错，不会擅自补全。明确不提供 DNS 的节点或仅配置外部 DNS 地址的节点不自动启用解析器。

节点由心跳恢复 pmmandns，配置目录默认为版本文件旁的 `pmmandns-config/`，可用 `PMMAN_PMMANDNS_CONFIG_DIR` 覆盖。旧版 `pmmandns` 可执行文件不会被当作配置目录。没有客户端在线时，配置失败仍写入节点日志；相同错误只在状态变化时输出。

检查监听和实际查询，不以节点在线状态代替 DNS 验收：

```bash
ss -luntp '( sport = :53 )'
journalctl -u pmman-network-node-<node-id>.service --since '10 minutes ago'
python3 probe-node-dns.py --server <gateway-ipv4> --server <gateway-ipv6>
```

`scripts/txgz/probe-node-dns.py` 不依赖额外 Python 包，分别检查双栈 UDP/TCP 的 A/AAAA 响应。国内 AAAA 按当前 pmmandns 策略返回 `NOERROR` 空答案是正常行为；超时、拒绝连接、`SERVFAIL` 不是正常行为。该脚本只验证查询路径；必要时再从已连接客户端验证隧道内的实际查询。

本地 `pnpm build`、musl Cargo tests/release 后执行 `scripts/deploy-txgz.ps1 -Version <version>`；后续发布使用 `build-server-release.ps1` 与 `publish-server-release-txgz.ps1` 分阶段执行。
通过真实公网页面创建接入配置、确认待接入及取消作废，再检查实际节点注册与重启恢复。
节点未显式创建并完成部署前，不应把公网主控验收描述为节点连通验收；客户端真实握手验收必须使用管理员刚创建的节点。
`scripts/txgz/verify_onboarding.py` 在 txgz 运行实际节点进程并验证接入及重启恢复，
会重启项目主控，仅清理自身生成的禁用测试节点；请在无活动客户端连接时执行。

- 注册 401：未预建 ID、配置中 ID/token 不匹配，或待接入记录已取消。
- 注册 400：UDP endpoint、公钥、DNS、分流前缀或路由表格式错误。
- 持续待接入：查看节点 systemd 日志、接口、公钥、主控 TLS 和配置路径。
- 已注册但离线：确认节点进程运行、出站心跳请求能到达主控。节点不监听 HTTP API。
- UDP 探测失败：检查独立探测监听、公网映射与防火墙；该端口不同于 WireGuard 端口。
- 握手失败：检查 UDP 防火墙、endpoint 和公钥；双栈流量失败则检查返回路由、策略规则和网关。
